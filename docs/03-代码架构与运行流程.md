# 代码架构与运行流程

## 1. 项目依赖方向

```text
OptiDiag.App (WPF)
    ├── OptiDiag.Application
    ├── OptiDiag.Infrastructure
    ├── OptiDiag.Protocols.Sff8472
    └── OptiDiag.I2c.Simulator

OptiDiag.Application
    ├── OptiDiag.I2c.Abstractions
    └── OptiDiag.Protocols.Abstractions

OptiDiag.Protocols.Sff8472
    └── OptiDiag.Protocols.Abstractions

OptiDiag.I2c.Simulator
    └── OptiDiag.I2c.Abstractions
```

最底层两个 Abstractions 项目只定义合同。协议项目不引用模拟器，模拟器也不引用 SFF-8472 解析器。

## 2. 从启动到显示数据

程序入口在 `App.xaml.cs`：

1. 创建 `Sff8472Simulator`。
2. 创建 `Sff8472Protocol`。
3. 用二者创建 `ModuleSession`。
4. 创建 `PollingEngine`、Dump 和 CSV 服务。
5. 创建 `MainWindowViewModel` 并显示 `MainWindow`。

窗口首次 Loaded 时自动调用 `ConnectAsync`。连接本身只改变适配器状态，随后 `ModuleSession.RefreshAsync` 完成一次完整采集。

## 3. 一次读取的调用链

```text
MainWindow
  -> MainWindowViewModel.RefreshAsync
    -> ModuleSession.RefreshAsync
      -> ModuleMemoryService.CaptureAsync
        -> II2cAdapter.TransferAsync
      -> IOpticalModuleProtocol.Decode
    -> ApplySnapshot
  -> WPF Binding 刷新界面
```

`Sff8472Protocol.CapturePlan` 描述要读取哪些区域。`ModuleMemoryService` 不理解温度或厂商字段，它只负责：

- 设置 Page Select。
- 读回 Page Select，拒绝未被模块接受的可选页面。
- 根据适配器最大长度分块。
- 串行化操作。
- 产生 `ModuleDump`。

`ShouldCaptureRegion` 允许协议根据已经采集到的能力位决定后续区域。例如 SFF-8472 先读 Page 02h 的 RPM 声明，再决定是否读取 Page 20h-27h；通信层不需要知道 RPM 是什么。

`Sff8472Protocol.Decode` 只接收 `ModuleDump`，所以可以对保存的文件离线解析，不必连接适配器。

## 4. 周期读取为什么不会重叠

`PollingEngine` 每轮等待 `RefreshAsync` 完成，再扣除本轮耗时并等待剩余间隔。若一次读取超过周期，它不会并发启动第二次读取，而是下一轮立即继续。

此外，`ModuleMemoryService` 使用 `SemaphoreSlim` 串行化所有采集、原始读取和写入。这样不会出现：

```text
线程 A 选择 Page 03h
线程 B 选择 Page 00h
线程 A 误把 Page 00h 当作 Page 03h 读取
```

## 5. ViewModel 的职责

`MainWindowViewModel` 持有供 WPF 绑定的集合：

- `Measurements`
- `Thresholds`
- `Alarms`
- `StatusItems`
- `Registers`
- `Diagnostics`
- `Logs` 和 `Traces`

它调用应用服务，但不拼装 I²C 字节。文件选择和最终写入确认留在 Window code-behind，因为它们属于 Windows 交互，而不是业务规则。

## 6. Dump 文件结构

`.omodump` 是 ZIP 容器：

```text
manifest.json
regions/a0.bin
regions/a2-lower.bin
regions/a2-page00.bin
...
```

清单记录格式版本、协议、采集时间、来源、地址和每个二进制区域的 SHA-256。加载时必须同时通过长度和哈希检查。

比较服务按区域和偏移逐字节比较，并保留 `Volatile` 标记。这样用户可以区分 EEPROM 静态变化和实时 DDM 变化。

## 7. 日志

应用日志同时显示在界面，并保存到：

```text
%LOCALAPPDATA%\OptiDiag\logs\OptiDiag-yyyyMMdd.log
```

I²C 事务日志包含时间、7 位设备地址、写入字节、读取字节、耗时和错误。显示集合限制为最近 1000 条，避免长时间轮询耗尽内存。
