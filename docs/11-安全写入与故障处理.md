# 安全写入与故障处理

## 1. 为什么原始写入是最高风险功能

光模块寄存器不是普通配置文件。一个字节可能同时包含只读状态、读写控制位和写 1 自清除命令；错误写入可能关闭发射、重新初始化 DataPath、清除诊断证据、改变密码或切换固件。

因此 OptiDiag 区分两类入口：

- **协议操作**：知道位域语义，例如 CDB 或固件下载状态机；
- **原始写入**：只知道地址和值，必须使用更严格的通用保护。

## 2. 风险分级

### 2.1 Blocked

以下字段禁止从原始写入口写入：

- `ReadOnly`；
- `ReadOnlyClearOnRead`；
- `Mixed`；
- `Reserved`；
- Lower Memory 的 Bank Select / Page Select。

`Mixed` 被禁止，是因为对整个字节写值可能覆盖同一字节中的只读状态或保留位。正确做法是实现专用协议命令，先掩码、保留不相关位，再写入允许改变的位。

选择器被禁止，是因为它们属于寻址机制。`ModuleMemoryService` 会原子选择并读回验证；绕过它会让后续读取落到错误页面。

### 2.2 Elevated

普通 `ReadWrite` 字段至少需要：

1. 本次操作解锁；
2. 显示地址、旧值、新值和风险说明；
3. 用户确认；
4. 写前读取当前值；
5. 当前值必须等于界面显示旧值；
6. 写入后回读必须等于请求值；
7. 记录审计日志。

### 2.3 Critical

以下字段还需要输入 `WRITE XX`：

- `WriteOnly`；
- `WriteOnlySelfClearing`；
- `ReadWriteSelfClearing`；
- `VendorSpecific`；
- 名称或说明包含 Reset、Apply、Commit、Password、Firmware、Laser、Disable 等危险语义。

对于自清除和只写字段，写后同值回读没有意义，系统会明确记录“按协议跳过同值回读”，而不是伪造验证成功。

## 3. 写入事务时序

```text
用户选择寄存器
  ↓
RegisterWritePolicy.Assess
  ├─ Blocked → 不发送事务
  ├─ Elevated → 普通确认
  └─ Critical → 输入 WRITE XX
  ↓
暂停 PollingEngine
  ↓
SafeRegisterWriter 读取当前值
  ├─ 与 UI 不同 → 取消，要求重新读取
  └─ 相同 → 继续
  ↓
ModuleSession → ModuleMemoryService → II2cAdapter
  ↓
可验证字段执行回读
  ↓
完整 Refresh，写审计日志，恢复轮询
```

## 4. 真实硬件操作前检查表

### 4.1 文档

- 已确认模块协议版本和厂商扩展版本；
- 已确认地址使用 7 位还是 8 位写法；
- 已确认字段访问属性、保留位和自清除行为；
- 已确认写入是否要求密码、状态机阶段或延时；
- 已确认掉电后是否保留。

### 4.2 环境

- 链路处于允许中断的维护窗口；
- 模块供电、电压和散热稳定；
- I²C 电平、上拉和速率符合模块要求；
- 已保存写入前 Dump；
- 已记录模块料号、序列号和当前固件；
- 有恢复方式，例如备用模块、复位流程或厂商工具。

### 4.3 操作

- 第一次只改变一个字段；
- 不同时运行另一个管理主机；
- 写入时停止高频轮询；
- 保存 I²C 日志；
- 写后读取状态机、告警和目标字段；
- 观察足够时间后再做下一步。

## 5. 常见故障

### 5.1 “寄存器已从 XX 变为 YY”

原因：界面快照已过期，可能来自轮询、模块内部状态机或另一主机。系统已经取消写入。重新读取、理解变化原因后再决定。

### 5.2 “写后回读不一致”

可能原因：

- 模块拒绝写入；
- 字段实际是自清除，但元数据标成普通 RW；
- 需要密码或特定状态；
- 页面/Bank 未被接受；
- 适配器没有正确产生重复起始或停止条件；
- 厂商实现偏离规范。

处理：保存事务日志和 Dump，不要连续重试。先根据规范检查访问条件。

### 5.3 读回了整页 00 或 FF

可能是无设备、未上电、地址错误、不支持该页、上拉问题或适配器用 8 位地址重复左移。不要把全 00/FF 自动解释成合法字段。

### 5.4 读取告警后告警消失

字段可能是 `ReadOnlyClearOnRead`。第一次读取已清除锁存证据。调试告警时应降低无关轮询，先保存原始状态再读取详细页。

### 5.5 写入后链路中断

立即停止进一步写入，记录：

- 最后一笔成功写；
- 所有后续错误；
- 模块状态和 DataPath 状态；
- 是否发生复位或低功耗切换。

若写的是触发型字段，回写旧值未必能撤销动作。应按协议状态机恢复，而不是盲目“写回”。

## 6. 审计日志格式

原始写入日志至少包含：

- 时间；
- 风险等级；
- 设备/Bank/Page/Offset；
- 旧值；
- 请求值；
- 回读值或跳过原因；
- 风险策略说明。

日志位于 `%LOCALAPPDATA%\OptiDiag\logs`。交付问题时同时提供日志和 `.omodump`，比截图更有价值。

## 7. 开发者规则

- 新增寄存器时必须标记正确 `RegisterAccess`。
- 不要为了“让按钮能点”把未知字段标成 `ReadWrite`。
- 混合位域必须提供专用的掩码写逻辑。
- 新增自清除命令必须有测试证明不会执行同值回读判断。
- 原始写入口必须经过 `RegisterWritePolicy` 和 `SafeRegisterWriter`。
- CDB、固件、DataPath 等专用工作流要有自己的状态机、超时和确认策略。
