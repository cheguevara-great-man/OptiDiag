# SFF-8472 协议导读

## 1. 规范解决什么问题

SFF-8472 定义 SFP/SFP+ 等模块的管理内存地图。主机不需要知道模块内部使用什么 MCU 或 ADC，只需按约定读取地址，就能得到模块身份、实时监控、阈值和告警。

当前实现基线为 SNIA 发布的 Rev 12.5a。老模块可能声明 9.x、10.x、11.x 或 12.4；解析器保留兼容码表，不会因为版本较老而拒绝读取。

## 2. A0h：身份和能力

A0h 对应 7 位地址 `0x50`，主要内容包括：

- 模块类型、连接器、兼容性代码和编码方式。
- 标称信令速率、链路长度或铜缆衰减。
- Vendor Name、OUI、Part Number、Revision。
- 波长、Serial Number、Date Code。
- 可选功能、数字诊断类型和 SFF-8472 版本声明。
- `CC_BASE` 和 `CC_EXT` 校验字节。

多字节数值默认是大端序，即低地址放最高有效字节。字符串是定长 ASCII，右侧通常用空格填充。

## 3. A2h lower：诊断数据

A2h 对应 7 位地址 `0x51`。下半区 0-127 主要分成：

```text
0-55    告警和预警阈值
56-94   外部校准常数或增强功能字段
95      CC_DMI
96-105  温度、电压、偏置、TX 功率、RX 功率
106-109 可选激光器温度和 TEC 电流
110     状态/软控制
112-113 Alarm flags
114-115 输入均衡和输出加重控制
116-117 Warning flags
118-119 扩展状态/控制
120-126 厂商自定义
127     Page Select
```

温度使用有符号 8.8 定点数。内部校准模块常用换算为：

```text
Temperature °C = signed_raw / 256
Voltage V      = raw × 100 µV
Bias mA        = raw × 2 µA
TX/RX mW       = raw × 0.1 µW
dBm            = 10 × log10(mW)
```

当模块声明 External Calibration 时，还需读取斜率、偏移和 RX 功率四次多项式系数。多项式结果的单位是 `0.1 µW`，转换为 mW 时乘 `0.0001`。相关实现集中在 `Sff8472Protocol.Calibration`，不会散落到界面代码中。

DWDM 可选监控的激光器温度同样使用有符号 8.8 格式；TEC 电流使用有符号二进制补码，LSB 为 `0.1 mA`，正值表示制冷，负值表示加热。

## 4. 阈值、告警和预警

阈值分四个等级：High Alarm、High Warning、Low Warning、Low Alarm。告警位由模块产生，不能简单地用当前数值重新计算代替，因为有些标志具有锁存或模块内部滞回行为。

界面同时显示：

- 模块报告的 flag。
- 当前测量值。
- EEPROM 中存放的阈值。

这样可以识别“数值正常但锁存告警仍有效”等情况。

## 5. 校验字节

`CC_BASE` 是 A0h bytes 0-62 的低 8 位求和；`CC_EXT` 是 bytes 64-94 的低 8 位求和；`CC_DMI` 是 A2h bytes 0-94 的低 8 位求和。有效 Page 03h 的 `CC_CALIB` 对 bytes 128-254 做同样校验。

校验失败不一定意味着通信彻底失败，也可能是厂商固件没有及时更新校验、模块在读取中发生变化或 Dump 被编辑。OptiDiag 会继续解码，但在“解码检查”中给出 Warning。

## 6. 页面

A2h byte 127 选择上半区 128-255 的页面。Rev 12.5a 涉及：

- Page 00h/01h：传统上半区和向后兼容区域。
- Page 02h：功能声明、RDT、远端性能监控；其中部分可调功能由 SFF-8690 定义。
- Page 03h：高精度时延校准。
- Page 20h-27h：支持 RPM 时的远端模块映射。
- Page 80h-FFh：厂商自定义。

本阶段解析 SFF-8472 自身定义的内容；引用其他规范或厂商定义的字段仍可原始读取，但不会猜测含义。

选择非零页面后，采集服务会读回 byte 127。若模块没有接受该页，规范要求其回到 `00h`；软件会把该页记为不可用，而不会误把 Page 00h 数据贴上 Page 02h/03h 的标签。Page 20h-27h 只在 Page 02h byte 129 声明 RPM 能力后采集。

## 7. SFF-8024 的作用

Identifier、Connector、Encoding 等公共代码由 SFF-8024 维护。它会独立更新，因此协议项目把码表查询集中在专用方法中。后续可进一步把公共码表抽成独立版本化项目，供 SFF-8636 和 CMIS 共用。
