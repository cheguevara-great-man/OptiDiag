# 从零学习与实战手册

## 1. 先建立一张完整地图

OptiDiag 是“光模块固件调试上位机”。这句话可以拆成四层：

1. Windows 应用负责交互、展示、保存文件和组织工作流。
2. I²C 层负责把“读取 0x50 的第 0 字节”变成总线事务。
3. 协议层负责解释字节，例如把 `19 80` 解释为 `25.5 °C`。
4. 应用层负责自动检测协议、按页面采集、周期读取、写入保护和日志。

不要把“协议”和“I²C”混为一谈。I²C 只运送字节；SFF-8472、SFF-8690 和 CMIS 决定字节的意义。

```text
用户点击
  ↓
MainWindow / MainWindowViewModel
  ↓
ModuleSession / PollingEngine / SafeRegisterWriter
  ↓
IOpticalModuleProtocol + ModuleMemoryService
  ↓
II2cAdapter
  ↓
模拟器或未来的 USB-I²C 设备
```

## 2. 第一次运行

### 2.1 最省事的方式

双击仓库根目录的 `run.cmd`。脚本会优先寻找用户目录中的 .NET SDK，不会重复安装 Visual Studio。

如果使用 Release 压缩包：

1. 把 ZIP 完整解压到普通目录。
2. 双击 `OptiDiag.App.exe`。
3. 不要只从 ZIP 预览窗口运行 EXE，因为依赖文件可能无法找到。

### 2.2 启动后发生了什么

程序读取 `%LOCALAPPDATA%\OptiDiag\settings.json`，应用主题和字号，创建三个模拟数据源，然后自动连接默认的 SFF-8472 模拟器。若启用了“启动时检查更新”，程序只查询 GitHub Release 元数据，不会下载或替换文件。

### 2.3 顶部工具栏

- **来源**：选择 SFF-8472、CMIS 5.3、CMIS 5.4 或未来的真实适配器。
- **模拟 SFF-8690**：让 SFF-8472 模拟模块声明可调谐扩展。
- **模拟 RPM 远端**：增加 Page 20h–27h，并解码为第二个远端模块。
- **周期**：轮询间隔。真实硬件不应盲目使用过短周期。
- **连接/断开**：管理 I²C 会话生命周期。
- **立即读取**：执行协议检测、内存捕获和解码。
- **周期读取**：持续刷新监控值并生成历史曲线。

## 3. 完成第一次只读调试

### 3.1 概览页

观察厂商、料号、序列号、协议声明、温度和电压。这里是“业务视图”，隐藏了大部分寄存器细节。

如果值异常，按以下顺序排查：

1. 查看“解码检查”是否报告缺页、校验错误或无效编码。
2. 打开“协议解析”，找到该字段的来源地址和公式。
3. 在“原始寄存器”查看对应字节。
4. 在“I²C 事务”确认读事务是否成功。

### 3.2 阈值、告警和状态

阈值是模块声明的边界，告警是当前或锁存的越界结果。两者不是一回事：

- 温度 90 °C 是测量值；
- 高告警阈值 85 °C 是边界；
- `TempHighAlarm = 1` 是告警标志。

“有效”表示该告警位当前为 1，不表示寄存器或数据“有效”。

### 3.3 曲线

开启周期读取后，`PollingEngine` 保存固定容量的内存历史。曲线不会无限增长；导出 CSV 后可用 Excel、Python 或其他工具分析。

## 4. 从语义回到寄存器

### 4.1 原始寄存器页

每行包含：区域、地址、HEX、DEC、ASCII、字段名、访问属性和说明。

同一个字节有三种常见表示：

```text
HEX  80
DEC  128
BIN  1000 0000
```

若规范说 Bit 7 为告警，则使用掩码：

```csharp
var active = (value & 0x80) != 0;
```

### 4.2 寄存器全景

全景页按每行 16 字节展示内存。地址 `A6` 位于行 `A0`、列 `06`。双击单元格可进入读写对话框；右键可明确选择只读或写入。

### 4.3 Page 和 Bank

CMIS 只有一个 8 位寄存器地址窗口，但通过 Lower Memory 的 Bank Select 和 Page Select 映射许多上层页面。选择错误时，屏幕仍可能返回“看起来正常”的 128 字节，却属于另一个页面，因此会产生最危险的静默错误。

OptiDiag 的会话层会：

1. 在一笔事务中原子写入 Bank/Page；
2. 读回选择器；
3. 仅在读回匹配后访问上层数据；
4. 禁止用户从原始写入入口直接修改选择器。

## 5. Dump 工作流

`.omodump` 是带元数据和 SHA-256 的模块内存快照。适合：

- 没有硬件时复现问题；
- 比较固件升级前后差异；
- 区分静态身份变化和动态监控变化；
- 把现场数据交给协议开发人员。

建议的命名：

```text
厂商-料号-序列号-固件版本-场景-时间.omodump
```

比较 Dump 时先看静态差异，再看动态差异。温度、功率、计数器变化通常正常；厂商名、能力位、校准常数变化需要解释。

## 6. 安全写入练习（只对模拟器）

1. 选择一个访问属性为 `ReadWrite` 的普通字段。
2. 勾选“写操作解锁”。
3. 输入新值。
4. 阅读风险说明并确认。
5. 查看应用日志中的旧值、新值、风险等级和回读结果。

系统实际执行：

```text
策略判断 → 用户确认 → 暂停轮询 → 读取当前值
→ 比对 UI 旧值 → 单次写入 → 回读验证 → 完整刷新 → 恢复轮询
```

如果当前值已变化，写入会取消。这叫“乐观并发检查”，用于避免旧界面覆盖模块刚刚发生的变化。

对于自清除、只写和厂商自定义字段，还需要输入 `WRITE XX`。这不是为了增加麻烦，而是阻止误触、键盘焦点错误和未经阅读的连续确认。

## 7. CMIS CDB 入门

CDB 是 CMIS 的命令通道，不是普通单字节寄存器。一次命令包含：

- Command ID；
- LPL（本地负载）；
- 可选 EPL（扩展负载）；
- 校验码；
- 执行状态和回复。

学习时先使用查询类命令。固件下载会执行 Start、分块 Write 和 Complete，但 OptiDiag 不会自动 Run 或 Commit，因为“传输完成”和“切换正在运行的固件”是两个风险等级不同的动作。

## 8. 日志如何阅读

应用日志回答“软件为什么这样做”，I²C 日志回答“总线上实际发了什么”。

一次典型分页读取会看到：

1. 向 0x50 的 126/127 写 Bank/Page；
2. 从 126 开始读回选择器；
3. 从 128 开始读取上层页面；
4. 解码器把结果映射为字段。

日志中的 0x50/0x51 是 7 位地址；规范中的 A0h/A2h 是包含读写位的 8 位传统名称。

## 9. 设置和更新

“设置与安全”页提供 Dark、Light、HighContrast 三套主题和基础字号。设置文件损坏时程序回退到安全默认值。

更新检查遵循最小权限：

- 只访问 `api.github.com` 的最新 Release；
- 不后台下载；
- 不自替换 EXE；
- 只打开公开 Release 页面；
- 用户自行核对版本、资产名称和 SHA-256。

## 10. 下一步学习任务

完成下面四项，说明你已经理解主流程：

1. 解释为什么 A0h 对应事务地址 0x50。
2. 根据来源地址手工算出一个温度值。
3. 解释 Page Select 为什么不能当作普通 RW 字节直接写。
4. 在一个解码器里增加只读字段，并写一项固定字节输入的单元测试。
