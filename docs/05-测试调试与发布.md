# 测试、调试和发布

## 1. 常用命令

```powershell
.\build.cmd

# 或者手动执行
dotnet restore .\OptiDiag.sln
dotnet build .\OptiDiag.sln
dotnet test .\OptiDiag.sln
dotnet run --project .\src\OptiDiag.App\OptiDiag.App.csproj
```

`build.cmd` 会先找 `%USERPROFILE%\.dotnet\dotnet.exe`，不存在时才使用 PATH 中的 `dotnet`。因此同一台电脑不会因为新终端 PATH 不同而被误判成“SDK 没安装”。

项目启用了 nullable、确定性构建和 TreatWarningsAsErrors。警告会让构建失败，避免把明显的空引用和类型问题拖到运行阶段。

## 2. 自动化测试范围

`OptiDiag.Protocols.Sff8472.Tests` 验证：

- 模拟 Dump 能被识别。
- 身份字段、DDM 和阈值换算。
- 可选分页采集。
- Page 20h-27h 的 RPM 条件采集。
- Page 20h-24h 的远端模块重组和语义解析，以及 25h-27h 的保留/厂商属性。
- SFF-8024 公共码表的已分配范围。
- A2h 56-74 增强功能和 Page 02h 的 RDT/RPM 结构。
- Page 03h 压缩日期、定点数时延与实时修正。
- SFF-8690 的声明、频率、网格、通道、误差和锁存告警。
- DWDM 可选温度、TEC 电流和告警位。
- 外部校准 RX 多项式的 `0.1 µW` 单位换算。
- 校验失败提示。

`OptiDiag.Core.Tests` 验证：

- 拒绝把 `0xA0` 当作 7 位地址。
- 会话采集和事务日志。
- `.omodump` 保存、加载、长度和 SHA-256。
- 静态/动态差异分类。
- 可写寄存器的模拟写入。
- 纯 SFF-8472 与带 SFF-8690 扩展的自动检测差异。
- CMIS Identifier/Revision 自动检测、B00/Pxx 原子选择和读回校验。
- CMIS 身份、阈值、8 通道监控、状态、告警及 Banked 寄存器写回。

未来增加硬件测试项目时，默认测试命令不能依赖插入设备；硬件测试应使用显式环境变量或测试分类手动启用。

当前 `.github/workflows/ci.yml` 会在 Pull Request 和 main 推送时使用 Windows runner 执行 Restore、Release Build、全部测试和 win-x64 自包含发布，并上传 TRX 与程序 Artifact。测试失败必须让进程返回非零退出码，禁止出现“输出显示失败但 CI 仍为绿色”。

Core 测试还覆盖写入风险分级、Bank/Page 选择器保护、写前防陈旧检查、写后回读、设置损坏回退和 GitHub Release 响应解析。

## 3. 调试建议

遇到数值异常时按层排查：

1. 查看 I²C 事务日志，确认地址、偏移和原始字节。
2. 保存 Dump，避免模块状态继续变化。
3. 在原始寄存器页确认大端字节组合。
4. 检查模块声明 Internal 还是 External Calibration。
5. 检查校验结果和协议版本。
6. 用单元测试固定该 Dump 和期望值，再修改解析器。

不要一边改 UI 一边猜换算公式；解析算法应该先在协议测试中得到确定结果。

## 4. 自包含发布

双击 `publish-win-x64.cmd`，或使用以下命令，生成无需安装 .NET 的 Windows x64 文件夹：

```powershell
dotnet publish .\src\OptiDiag.App\OptiDiag.App.csproj `
  -c Release `
  -r win-x64 `
  --self-contained true `
  -o .\artifacts\OptiDiag-win-x64
```

运行入口为：

```text
artifacts\OptiDiag-win-x64\OptiDiag.App.exe
```

当前不启用单文件压缩，因为多文件发布启动更快、诊断更直观，也方便以后加入厂商原生 DLL。正式给生产或客户使用前，还应增加代码签名、版本信息、安装包和升级策略。

## 5. VS Code

仓库包含 `.vscode/tasks.json` 和 `.vscode/launch.json`。安装微软 C# 扩展后可按 F5 启动；不安装扩展也能直接使用上面的 `dotnet` 命令。

Visual Studio 不是构建、测试或发布本项目的前置条件。若以后希望使用 XAML 可视化设计器，可以选择安装，但命令行 SDK 已能完成全部开发流程。
