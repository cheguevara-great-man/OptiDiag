# 真实硬件接入指南

## 1. 当前边界

OptiDiag 已把 I²C、协议、应用服务和 WPF 解耦，但没有在未知设备型号的情况下伪造 CH341、CH347 或 FTDI 支持。真实后端能否工作取决于：

- USB-I²C 芯片和板卡型号；
- 驱动与 DLL 位数；
- 厂商 API 的事务能力；
- 模块供电、复位、ModSelL 和 LPMode 控制；
- 电平、电压、上拉和总线拓扑。

只提供“CH347”四个字通常还不够，同一芯片可能出现在接线和固件不同的板卡中。

## 2. 需要收集的资料

接入前请准备：

1. 适配器完整型号和照片；
2. 厂商 SDK、DLL、头文件和示例；
3. 32/64 位要求和驱动安装包；
4. I²C 最大读写长度；
5. 是否支持组合写后读和 Repeated START；
6. 总线速率设置方式；
7. 模块插座的供电、电平和控制脚；
8. 一个已知正常模块及其协议；
9. 厂商工具读取的参考 Dump；
10. 允许做破坏性测试的样品范围。

## 3. `II2cAdapter` 合同

真实后端实现 `II2cAdapter`，核心责任是：

- `OpenAsync`：打开唯一设备并配置安全速率；
- `CloseAsync`：释放句柄；
- `ReadRegistersAsync`：从 7 位地址和 8 位寄存器偏移读取；
- `WriteRegistersAsync`：发送寄存器偏移和负载；
- 报告 `MaximumReadLength`、`MaximumWriteLength`；
- 每笔事务触发 `TransferCompleted`，包含耗时和错误。

适配器不应该：

- 解析 SFF 或 CMIS；
- 自行缓存 Page；
- 把 0x50 再当成 A0h 左移两次；
- 静默吞掉 NACK；
- 在失败时返回全 00 假数据。

## 4. 地址约定

项目内部永远使用 7 位地址：

| 规范传统名称 | 7 位地址 | 写地址字节 | 读地址字节 |
|---|---:|---:|---:|
| A0h | 0x50 | 0xA0 | 0xA1 |
| A2h | 0x51 | 0xA2 | 0xA3 |

如果 SDK 要求 8 位地址，转换只能发生在具体适配器内部一次，并写入该适配器文档和测试。

## 5. 分阶段接入

### 阶段 A：设备发现

只实现枚举、打开和关闭。重复插拔 50 次，确认无句柄泄漏、无僵尸设备。

### 阶段 B：最小只读事务

读取 0x50:0。检查 Identifier 是否合理，再读取一小段厂商信息。此时禁止任何页面选择和写入。

### 阶段 C：块读和边界

测试长度 1、2、16、32、128；测试从 0x7F、0x80、0xFF 附近开始的边界。上位机必须在 256 字节窗口前拆分或拒绝事务。

### 阶段 D：分页

先用模拟器和记录适配器验证事务序列，再接真实 CMIS：

```text
WRITE 0x50 @126 [bank, page]
READ  0x50 @126 length 2
READ  0x50 @128 length N
```

读回不匹配时必须停止，不能继续解析。

### 阶段 E：普通写入

只选择厂商明确允许、可恢复、不会影响链路的测试字段。保存写前 Dump，执行写前核对和写后回读。

### 阶段 F：状态机和固件

只有前五阶段稳定后才测试 DataPath、复位、自清除命令和固件更新。固件测试需要可恢复样品和厂商流程。

## 6. 推荐项目结构

```text
src/
  OptiDiag.I2c.Abstractions/
  OptiDiag.I2c.Ch347/          # 示例：具体后端独立程序集
    Ch347Adapter.cs
    NativeMethods.cs
    Ch347Options.cs
tests/
  OptiDiag.I2c.Ch347.Tests/
```

不要把 DLL P/Invoke、协议字段和 WPF 对话框放在同一个文件。

## 7. 测试替身

真实后端至少需要三类测试：

- **纯单元测试**：参数校验、地址转换、块拆分；
- **记录回放测试**：输入厂商 API 调用结果，验证事务序列；
- **硬件测试**：带显式环境变量或标签，默认 CI 不运行。

硬件测试不能只断言“没有抛异常”，还应验证 Identifier、厂商字符串、分页读回和可重复性。

## 8. 硬件接入验收标准

- 连续读取 1 小时无页串扰；
- 拔插后能恢复，错误信息明确；
- NACK、超时、断线不会返回伪数据；
- 事务日志与逻辑操作一一对应；
- 读写长度遵守后端能力；
- SFF-8472 和 CMIS 至少各有一个真实 Dump 对照；
- 所有危险写默认不可用或需要明确确认；
- 发布包包含合法可分发的运行库，并写清驱动来源。
