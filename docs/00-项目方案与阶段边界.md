# 项目方案与阶段边界

## 1. 产品目标

OptiDiag 面向光模块固件开发和问题定位。它把“字节怎么传输”“字节代表什么”“怎样展示和保存”分成独立层，先用确定性的模拟器完成整套软件，再接入用户最终选定的 I²C 适配器。

当前可运行基线是 Windows、C#、.NET 10、WPF、SFF-8472 Rev 12.5a、CMIS 5.3 和正式版 CMIS 5.4。没有真实硬件时，软件仍可演示协议自动检测、采集、解析、轮询、曲线、写保护、Dump、比较、CSV 和日志的完整流程。

## 2. 分层方案

```text
WPF 界面
  ↓ 只调用 ViewModel
应用层：会话、采集、周期读取
  ↓                    ↓
I²C 抽象/模拟器        协议抽象/SFF-8472/CMIS
  ↓                    ↓
适配器事务             ModuleDump → 通用领域模型
  ↓
Dump、比较、CSV、日志基础设施
```

核心约束：

- I²C 层只处理 7 位地址和字节事务，不解释温度或厂商名。
- 协议层只读取 `ModuleDump`，不打开 USB 设备，也不依赖 WPF。
- 界面不直接拼接 I²C 命令。
- 分页选择与实际读取必须串行，非零页面必须读回验证。
- 写操作默认锁定；只读、读清除、Mixed、Reserved 和 Bank/Page 选择器无法从原始入口写入。普通 RW 字段执行写前旧值核对和写后回读，高风险字段还需要输入确认，并保留审计日志。
- 提供 Dark/Light/HighContrast、基础字号和本地偏好保存；版本检查不自动下载或替换程序。
- GitHub Actions 在 Windows 上自动完成 Release 构建、测试和自包含包验证。

## 4. 开发阶段

第一阶段已经形成的软件基线：

- SFF-8472 身份、完整公共码表、链路能力、标准/可选 DDM、阈值、告警、控制状态和寄存器属性。
- 内部/外部校准以及四类校验码。
- Page 02h RDT/RPM、Page 03h 高精度时延以及 SFF-8690 可调谐扩展。
- 按 RPM 声明采集 Page 20h-27h，并把标准映射部分重组为第二个模块解码。
- 软件/真实数据源选择和管理协议自动探测；模拟器可切换是否声明 SFF-8690。
- CMIS 5.3 平面/分页模型、基础规范定义的 Page、最多 32 通道监控、可调谐激光器、诊断、Network Path、NAD、HLS 和 VDM。
- CMIS 5.3 Chapter 9 的 48 个 CDB 命令合同、LPL/EPL 编解码、执行状态机、回复解析和安全固件下载流程。
- CMIS 5.4 的新增 Page、最多 256 Lane、255 个 NAD Bank、系统化能力位图、52 个版本有效 CDB 命令和固件管理扩展；5.3 模拟器与命令视图继续保留。
- 软件模拟、周期读取、趋势、日志、导出、Dump 保存与比较。

后续在确定硬件后增加一个独立的 `OptiDiag.I2c.<Adapter>` 项目，并使用真实 Dump 做回归测试。协议侧可继续增加 SFF-8636、SFF-8436、CMIS 外部补充规范和公司自定义协议；现有 SFF-8472 与 CMIS 基础解析器无需被重写。

## 5. 当前明确不做的事情

- 不猜测尚未提供的 USB-I²C 厂商 API、驱动或私有解锁命令。
- 不猜测 Page 26h/27h 或公司私有字段的厂商含义；这些字节保持原始可见并标记为 Vendor Specific。
- 不要求安装 Visual Studio。当前用户目录中的 .NET SDK 足以构建，发布包可在未安装 .NET 的电脑运行。

真实硬件阶段至少需要适配器型号/API 文档、驱动、连接方式，以及一份去敏的正常模块 Dump。公司自定义协议还需要寄存器表、访问权限、比例单位、页/Bank 规则和解锁流程。
