# 扩展与开发指南

## 1. 增加真实 I²C 适配器

创建新的类库，例如：

```text
OptiDiag.I2c.Cp2112
OptiDiag.I2c.CompanyBoard
```

实现 `II2cAdapter`：

- `OpenAsync`：枚举并打开设备。
- `CloseAsync`：停止挂起事务并释放句柄。
- `TransferAsync`：把 7 位地址、写缓冲和读取长度转换为厂商 API。
- `TransferCompleted`：无论成功或失败都产生事务记录。
- `DisposeAsync`：可靠释放 HID、串口或 DLL 资源。

适配器不得引用 WPF，也不应解释任何 SFF 字段。对于不支持 Repeated START 的设备，需要在适配器项目中明确其事务语义和限制。

## 2. 增加新协议

新建协议类库并实现 `IOpticalModuleProtocol`：

```text
Id              稳定的机器标识
DisplayName     界面名称
Revision        实现所依据的规范版本
CapturePlan     默认采集区域
ShouldCaptureRegion  根据已采集能力位跳过不适用区域
CanDecode       根据 Identifier/Revision 判断能否解析
Decode          内存快照 -> 通用领域模型
```

建议顺序：

1. SFF-8636 Rev 2.12。
2. 为旧模块增加 SFF-8436 兼容解析器。
3. CMIS 5.4；同时扩展 Bank/Page 地址策略。
4. 公司自定义协议。

SFF-8436 与 SFF-8636 有历史继承关系，但应保留独立的版本检测和兼容测试，不要简单复制解析结果。

## 3. 公司自定义协议

简单协议可增加 JSON 寄存器描述：地址、位域、访问权限、单位、比例和枚举。复杂协议应使用 C# 插件，因为解锁序列、动态页面、校验或跨字段公式很难用静态表准确表达。

正式实现前至少需要：

- 7 位设备地址。
- 页/Bank 选择方式。
- 完整寄存器表和版本号。
- 大小端、定点格式、比例和单位。
- 读写权限、密码/解锁流程、写周期。
- 校验算法和告警锁存规则。
- 一份去敏后的真实 Dump 和期望解析结果。

## 4. 增加字段

SFF-8472 字段解析集中在 `Sff8472Protocol.cs`。新增字段时应同时完成：

1. 在领域模型中确定通用表达；若只属于一个协议，避免污染所有协议的公共模型。
2. 增加大端/有符号/定点换算。
3. 为原始寄存器增加名称、说明和访问权限。
4. 添加至少一个正常值测试和一个边界/非法值测试。
5. 在协议导读中补充含义。

## 5. 兼容策略

- 未知枚举显示原始十六进制，不抛异常。
- Reserved 位不要求读回为零。
- 可选页面读取失败产生 Warning，不使整个基础读取失败。
- 有明确能力位的页面先用 `ShouldCaptureRegion` 判断，避免无意义探测。
- 校验失败继续解析，但显著提示。
- 厂商字段保持原始可见，不猜测语义。
- 解析器不得修改传入 Dump。
