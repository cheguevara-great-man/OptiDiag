# 上位机与 I²C 入门

## 1. 什么是上位机

在嵌入式开发中，“下位机”通常是单片机、光模块、传感器或控制板，“上位机”是在电脑上运行、用于观察和控制下位机的软件。

OptiDiag 做四件事：

1. 发出读取或写入请求。
2. 把设备返回的原始字节保存下来。
3. 按 SFF-8472 等协议把字节解释成厂商、温度、电压和告警。
4. 用表格、曲线、日志、Dump 和差异报告呈现结果。

“通信成功”和“数据解释正确”是两个不同问题。I²C 层只保证得到一串字节；协议层才知道 `0x20 0x00` 是温度、字符串还是两个独立标志。项目刻意把两者分开。

## 2. I²C 的两根信号线

I²C 的主要信号是：

- `SCL`：时钟，由控制器产生。
- `SDA`：双向数据线。

两根线通常都是开漏输出，需要上拉电阻。真实接线时还必须共地，并确认上拉电压、模块供电、电流能力和引脚定义。软件不能弥补电压接错或没有共地。

电脑上的 USB-I²C 适配器扮演控制器，光模块是目标设备。一次典型的寄存器读取是：

```text
START
目标地址 + Write
寄存器偏移
Repeated START
目标地址 + Read
模块返回 N 个字节
STOP
```

其中 Repeated START 很重要：它让“先指定偏移，再读取数据”保持为同一个逻辑事务。

## 3. ACK、NACK 和常见失败

每个字节后接收方会返回 ACK。NACK 表示没有设备响应、设备忙、地址错误或当前操作不支持。

常见问题包括：

- 把规范里的 A0h 直接当作 7 位地址 `0xA0`，实际应传 `0x50`。
- 读取长度超过适配器或模块限制。
- 页面选择和数据读取之间被另一条线程插入操作。
- 写入 EEPROM 后没有等待内部写周期。
- 模块掉电或被拔出时仍在轮询。

OptiDiag 用单一请求队列串行执行事务；页面选择和页面读取由同一把锁保护，避免并发切页。

## 4. 地址为什么有两种写法

传统资料经常把 7 位地址左移一位，再把最低位作为读写位：

```text
7 位地址 0x50 -> 写地址字节 0xA0，读地址字节 0xA1
7 位地址 0x51 -> 写地址字节 0xA2，读地址字节 0xA3
```

SFF-8472 沿用 A0h/A2h 作为存储区名称。现代 API 一般要求传 7 位地址，因此项目内部只接受 `0x00-0x7F`，传 `0xA0` 会立即报错。

## 5. 模拟器如何代替硬件

`Sff8472Simulator` 在内存中维护 A0h、A2h lower 和多个上半区页面。它遵守和真实适配器相同的 `II2cAdapter` 接口：

- 读取时必须先写寄存器偏移。
- A2h byte 127 控制当前页面。
- 未知设备地址返回模拟 NACK。
- 每次事务产生带时间和耗时的日志。
- DDM 值随时间缓慢变化。

所以界面、轮询、Dump 和协议解析不会知道自己连接的是模拟器。未来换成真实硬件时，上层代码不变。

## 6. 写寄存器为什么需要保护

光模块中部分字节是只读身份信息，部分是状态位，部分是软控制，还有部分是厂商私有或密码保护区。盲目写入可能造成激光器关闭、模块配置损坏或 EEPROM 寿命下降。

当前界面采用三层保护：

1. 默认关闭写操作。
2. 只读和 Reserved 字段始终不能写。
3. 写入前再次确认，并记录地址、旧值和新值。

真实硬件接入后还应增加写后校验、EEPROM 写周期等待和公司自定义解锁流程。
